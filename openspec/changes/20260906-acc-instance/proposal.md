# 20260906-acc-instance — proposal

## Why

HG-40 asked for Hermes-style *profiles*: named things that "maintain their own
memory, registry and sessions". `20260817-named-deployment-profiles` shipped a
**posture** — a validated, reversible set of configuration keys — and left its
first open question standing: *does a profile isolate state, or only
configuration?* The vault re-read (HG-40.1, 2026-09-04) answered it: the word
"profile" is overloaded three ways (deployment posture, TUI view, and what
Hermes means), and what Hermes means is a different thing — an **instance**:
a collective with its own memory, sessions, trace and voice, **owned by one
principal**, running under one posture.

What the tree says on 2026-09-06 (this change verified it; HG-40.1 had two
stale claims):

* Isolation by `collective_id` already exists and is complete for the bus, the
  working state and the vector store: NATS `acc.<cid>.*`, Redis `acc:<cid>:…`,
  the LanceDB `collective_id` column plus a per-agent path.
* Two roots are **not** partitioned that way: the tracelog (`ACC_TRACELOG_DIR`,
  one shared `/logs` mount for every cell) and the TUI's sessions
  (`ACC_SESSIONS_DIR`). Both are plain directories read from the environment.
* Overlays come from the role dir plus a `collective.md` found in the **cwd**;
  a cell has no way to be told which collective voice it runs under.
* There is no `acc/sub_collectives.py`; sub-collectives are
  `SubCollectiveSpec` entries the hub's assistant consults for routing, plus
  `acc-deploy.sh resume|hibernate <cid>` over a compose preset that **no
  preset on disk provides**. `acc-deploy.sh new-stack` / `acc.pkg.stack`
  generate a collective definition per name. Nothing binds any of it to a
  person or to a posture.
* The TUI acts as `tui:anonymous` on decisions and board actions (D-011's
  open item) and its prompts carry no requester. `identity.current()` resolves
  the person at the keyboard from the substrate and is used only by
  `access whoami/admit` and the sessions index.

So the instance is a **binding**, not a mechanism: one directory that holds
the collective definition (the installed set), the overlays and every state
root, an `instance.yaml` naming the owner, the posture and the hub, and the
environment that points the cells and the surfaces at it.

## What

**The record** — `instances/<id>/instance.yaml` (`ACC_INSTANCES_DIR`):

```
id: alice-dev            # the collective id — a DNS label
owner: system:alice      # a Principal attribution; kubernetes / system / web only
profile: edge-lean       # the posture (must exist); "" = none
hub: enterprise          # optional; "" = standalone
stack_profile: edge      # which control agents run (acc.pkg.stack.PROFILES)
created_by / created_at / note / archived
```

**The directory** — `collective.yaml` (generated by `acc.pkg.stack`, control
set + `--agent` roles + `--pack` installed set, `collective_id = id`),
`overlays/collective.md` (the instance's voice above the shared roles),
`lancedb/`, `sessions/`, `trace/`.

**The environment** — `cell_env()` for every cell: `ACC_COLLECTIVE_ID`,
`ACC_INSTANCE_ID`, `ACC_INSTANCE_OWNER`, `ACC_LANCEDB_PATH=…/lancedb/{aid}`,
`ACC_TRACELOG_DIR`, `ACC_COLLECTIVE_DIR`, `ACC_HUB_COLLECTIVE_ID` when bound;
`cell_volumes()` mounts `instances/<id>/{lancedb,trace}` with `U,z` (the
cell's sub-uid owns them — rootless podman), `overlays/` read-only, and not
`sessions/` (the TUI's, on the host).
`roles_to_compose(extra_env=, extra_volumes=)` stamps every synthesised cell (worker-pool
cells too; `{aid}` resolved per cell). `surface_env()` gives the TUI / CLI the
same instance with host paths. The agent takes its overlay dir from
`ACC_COLLECTIVE_DIR` before the cwd convention.

**The commands** — `acc-cli instance create|list|show|archive|export|import|
synth|env`; `./acc-deploy.sh instance up|down|synth <id>` renders the overlay
and runs it beside the base stack (NATS, Redis). `archive` never deletes
state; `memory forget` is erasure.

**Distribution** — `export` carries the definition: the collective
(installed set), the overlays, the posture as `profile export` renders it, the
hub binding. It carries **no owner** (a principal of *this* substrate) and
**no state**, and the document lists what it left behind. `import` creates a
new instance owned by the importing principal; the posture is installed under
its name when absent, never applied. The `signature` field is reserved: the
moment an archive travels, §12.3 of the profiles spec is live.

**The TUI carries its owner** — `acc/tui/actor.py` resolves the principal
once (`identity.current()`); decisions carry it as `approver_id`, board
actions as `actor`, and every prompt is attributed the way a channel adapter
attributes an admitted requester (`requested_by`, subject, tier, ceiling;
`requester_source` stays `tui`, so the memory scope stays pooled by policy
while the *person* is known — quorum and attribution count people). An
unattributed TUI still works (`tui:anonymous`, no attribution).

## Decisions

* **Instance, not profile.** `profile` keeps the shipped posture command;
  `instance` is the binding (HG-40.1 Q5).
* **Owners are vouched.** An external identity cannot own an instance, for
  the reason it cannot be an operator.
* **T2 is the shape** (HG-40.1 Q1, still awaiting the operator's confirmation):
  an instance is a whole collective. T1 (many people in one collective) is
  the team agent and needs the per-requester views of HG-40.1b, not this.
* **Packs are not copied.** The registry stays shared and content-addressed;
  isolation lives in the installed set, which is the instance's
  `collective.yaml`.

## Not here

The hub memory scope, the curator role, per-requester views, cross-instance
erasure, retention (HG-40.1b); signing of the export archive (§12.3 — the
field is reserved); hibernation of an instance with state intact (the
sub-collectives lifecycle already stops containers and keeps volumes; the
instance's roots are bind mounts, so they survive by construction, untested
here); the Web GUI attaching to an instance (it takes `ACC_COLLECTIVE_IDS`
like any surface, but its sessions/trace roots are not yet instance-aware).
